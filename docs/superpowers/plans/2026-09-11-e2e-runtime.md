# End-to-end runtime implementation plan

1. Inventory selected tests, shared state, fixed delays, and existing normal-test
   coverage. Establish a local execution path and collect timings.
2. Move challenge form permutations to component tests with equivalent request
   and preference assertions. Combine duplicate profile journeys.
3. Correct launcher exit status and context ownership. Remove unconditional
   delays and machine-wide process cleanup. Validate the harness itself.
4. Replace global moderation assumptions with report-specific checks and isolate
   mutable seeded state. Move suitable timer and history checks to normal tests.
5. Enable parallel execution, run the complete automated selection, and fix
   failures from observable evidence. Repeat successful runs without retries.
6. Update the coverage map and timing results in `docs/e2e-testing.md`. Run Jest,
   type-check, lint, formatting, graphify update, and one build.

Initial environment: the frontend and backend run in Docker. Dependencies are
in the frontend container. The host graphify executable and graph output are
absent. Git signing has no local secret key; local documentation commits use
`git -c commit.gpgsign=false`.

Implemented scope:

- Automated journeys are reduced from 86 to 72 browser tests, with client
  coverage in Jest and first-turn policy coverage in backend pytest. The old
  unfiltered command also selected four utilities and two visual checks (92
  entries total); those six remain available outside the automated selection.
- API account fixtures, report-specific checks, worker-specific malicious-report
  filers and ladder players, and confirmed vote responses replace shared state and fixed waits.
- A built-asset runner defaults to six workers and forwards backend traffic
  through the supplied development frontend. Dev-server tests retain that
  frontend. The CI companion runs one full batch without implicit quarantine.
- Browser failures exposed a warning countdown gap and a Kibitz default-room
  navigation race, plus a snapshot copier that removed shared player data. These
  receive product fixes and focused regression checks. Existing UI selectors and input
  readiness checks are corrected from traces. Reused Home pages select the
  current challenge by ID, and browser actions have bounded default waits.
- Backend first-game browser-ID policy tests supplement the retained suspension
  delivery browser test. Unranked moderation fixtures avoid unrelated external
  AI analysis and rating tasks. Account updates publish after commit to prevent
  warning requests from reading uncommitted message state.

Validation: all 546 frontend tests and 336 backend tests pass (five existing
backend skips). TypeScript, frontend lint, Python lint/format, and the build
pass. The backend aggregate `make lint` stops in the separate baduk.com app on
missing Node types in its Vite configuration. Graphify is not installed.

Measurements and final repeated browser results are recorded in the durable
testing guide. Builds were refreshed after frontend product fixes changed;
service startup, dependency installation, and builds are separate measurements.
